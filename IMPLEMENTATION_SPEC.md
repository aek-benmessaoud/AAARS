# Project11-AAARS — Implementation Specification

## 0. Objective

Create a **new, independent project** called:

`Project11-AAARS`

AAARS = **Allocation-Aware Adaptive Richness Stopping**.

The objective is to transform the current richness-based stopping work into a genuinely **adaptive online algorithm**, while preserving the previous implementation completely unchanged.

### Critical requirement

**DO NOT MODIFY, DELETE, RENAME, OR OVERWRITE ANYTHING IN THE EXISTING PROJECT.**

The old implementation is the baseline/reference implementation and must remain reproducible exactly as it currently is.

Create:

```text
Project11-AAARS/
```

as a new project.

The new project may reuse/copy code from the old project, but modifications must occur **only inside `Project11-AAARS/`**.

---

# 1. Scientific objective

The previous work established an important empirical observation:

- systematic/boustrophedon allocation + Chao1 stopping → reliable in tested configurations;
- locality-driven allocation + Chao1 stopping → substantial false certification;
- Chao92-inspired conservative stopping is safer but can be excessively conservative.

The new project must turn this observation into a **new online adaptive algorithm**.

The core idea is:

> Do not choose Chao1 or a conservative estimator permanently based only on the known allocation policy. Instead, continuously monitor the statistical characteristics of the observations generated by the robots and adapt the stopping mechanism online.

The new algorithm should therefore learn from the **observation process itself**, not from ground truth.

---

# 2. Core AAARS concept

Implement:

## Allocation-Aware Adaptive Richness Stopping

At runtime, AAARS repeatedly performs:

```text
robot allocation
       ↓
detection observations
       ↓
observation-process diagnostics
       ↓
allocation / temporal-clustering state
       ↓
estimator selection
       ↓
confidence-bound evaluation
       ↓
STOP / CONTINUE
```

The algorithm must NOT use:

- true number of targets;
- true recall;
- hidden target locations;
- oracle stopping information;
- simulator-only ground truth.

Ground truth may be used **only by evaluation scripts**, never by the online AAARS decision.

# 5. ObservationMonitor

Create a component that maintains online statistics from robot observations.

It must track at least:

```text
n_det
f1
f2
f3...
number of detection occasions
number of active locations
number of repeated observations
inter-detection intervals
revisit intervals
```

Do not rely only on the existing eight-occasion bitmask.

Maintain a clearly defined statistical observation window.

The implementation must support configurable:

```text
window_size ∈ {4, 8, 16, full_history}
```

The default should initially remain:

```text
window_size = 8
```

to preserve comparability with the previous experiments.

# 6. Temporal clustering diagnostics

This is a central new component.

AAARS must estimate whether observations are temporally dispersed or clustered.

Implement at least three online diagnostics.

## 6.1 Inter-detection interval statistic

For each detection event:

```text
Δt_i = t_i - t_{i-1}
```

Maintain:

```text
mean_Δt
std_Δt
coefficient_of_variation_Δt
```

Define:

```text
CV_Δt = std(Δt) / (mean(Δt) + ε)
```

---

## 6.2 Revisit interval statistic

For every detected location:

```text
revisit_interval = current_time - previous_visit_time
```

Maintain:

```text
mean_revisit
std_revisit
CV_revisit
```

Small revisit intervals indicate concentrated/local search behavior.

---

## 6.3 Temporal clustering score

Implement a normalized clustering score:

```text
TCS
```

using the available inter-event statistics.

Start with a simple robust formulation:

```text
TCS = normalized(
          CV_Δt
          + CV_revisit
          + short_revisit_fraction
      )
```

The exact implementation must be documented and deterministic.

Do not arbitrarily claim that this is a theoretically optimal clustering measure.

It is an **online diagnostic feature**.

---

# 7. Spatial concentration diagnostic

Because the paper concerns allocation, temporal behavior alone is insufficient.

Maintain a spatial concentration measure.

For recent detection locations:

1. divide the environment into spatial bins;
2. count observations per bin;
3. compute normalized concentration.

Possible implementation:

```text
SpatialConcentration =
    sum(p_i^2)
```

where:

```text
p_i = observations_in_bin_i / total_observations
```

This is a normalized concentration/Herfindahl-type measure.

Also compute:

```text
unique_bins / total_observations
```

as a dispersion measure.

The module must expose:

```text
spatial_concentration
spatial_dispersion
```

---

# 8. Frequency-spectrum diagnostics

Maintain:

```text
f1
f2
f3
...
```

and especially:

```text
f1/f2
```

with safe handling when:

```text
f2 = 0
```

Also compute:

```text
singleton_fraction = f1 / S_obs
doubleton_fraction = f2 / S_obs
```

and their recent temporal trends.

Compute:

```text
Δ(f1/f2)
```

over a configurable diagnostic window.

This is important because the previous study showed that the frequency spectrum is related to stopping reliability.

---

# 9. Observation-quality state

Combine the diagnostics into an online state.

Define:

```text
Q_obs
```

with values:

```text
DISPERSED
MODERATE
CLUSTERED
```

The initial implementation may use a transparent rule-based classifier.

For example:

```text
if temporal_clustering < τ_low
   and spatial_concentration < σ_low:
       state = DISPERSED

elif temporal_clustering > τ_high
     or spatial_concentration > σ_high:
       state = CLUSTERED

else:
       state = MODERATE
```

Do NOT tune these thresholds using test episodes.

Threshold selection must be performed using a dedicated discovery/training set.

# 11. EstimatorSelector

Create an estimator selector:

```text

```

Initial policy:

```text
DISPERSED  → Chao1-CI
MODERATE   → conservative Chao-based bound
CLUSTERED  → Chao92-inspired conservative bound
```

The selector must be configurable.

For example:

```text

```

Later support:

```text

selector_mode = fixed_conservative
selector_mode = AAARS
```

This allows direct ablation.

---

# 12. Hysteresis

Do NOT switch estimator every single timestep.

Otherwise AAARS can oscillate:

```text
Chao1 → conservative → Chao1 → conservative...
```

Implement hysteresis.

Example:

```text
state must remain different for M consecutive decision intervals
```

before switching.

Default:

```text
M = 3
```

Make this configurable.

Record every estimator transition.

---

# 13. Minimum evidence gate

Keep the previous arming concept but make it part of AAARS.

Initial default:

```text
n_det >= 5
f2 >= max(5, ceil(0.08*n_det))
```

Do not silently change these values.

Make them configuration parameters:

```text
N_MIN = 5
F2_MIN = 5
F2_RATIO = 0.08
```

The experiment framework must be able to perform sensitivity analysis later.

---

# 14. Adaptive confidence threshold

The stopping rule should remain conservative.

For the selected estimator:

```text
residual_upper_bound <= α * estimated_total
```

with:

```text
α = 0.05
```

initially.

Interpretation:

```text
estimated residual <= 5% of estimated total
```

This is an operational proxy for the 95% recall objective.

Do NOT call this a mathematical guarantee of 95% recall.

---

# 15. Conservative safety margin

AAARS should optionally add an allocation-risk margin.

Define:

```text
risk_multiplier
```

based on observation state.

Initial design:

```text
DISPERSED:
    margin = 1.00

MODERATE:
    margin = 1.10

CLUSTERED:
    margin = 1.25
```

Then use:

```text
adjusted_upper_bound =
    risk_multiplier * residual_upper_bound
```

and stop only if:

```text
adjusted_upper_bound <= 0.05 * estimated_total
```

IMPORTANT:

These values are starting parameters, not claimed optimal values.

They must later be calibrated on a discovery set.

---

# 16. Why this is a new algorithm

The key new operation is:

```text
observe → diagnose allocation-induced statistical risk
       → select estimator / safety margin
       → evaluate stopping condition
```

The algorithm is therefore not merely:

```text
run Chao1
```

and not merely:

```text
run Chao92
```

It is:

```text
AAARS = online observation-process diagnosis
        + adaptive estimator selection
        + risk-adjusted stopping
```

This is the main algorithmic contribution to test.

# 17. AAARS pseudocode

Implement approximately:

```text
Algorithm AAARS

Input:
    robot observations
    allocation policy
    stopping threshold α
    diagnostic thresholds
    minimum evidence parameters

Initialize:
    observation monitor
    temporal statistics
    spatial statistics
    frequency statistics
    current estimator = Chao1
    current state = UNKNOWN

For every decision interval:

    collect new observations

    update:
        n_det
        f1, f2, ...
        temporal statistics
        revisit statistics
        spatial concentration
        f1/f2 trajectory

    if minimum evidence not satisfied:
        continue

    compute:
        temporal clustering score
        spatial concentration
        frequency stability

    classify observation state:
        DISPERSED
        MODERATE
        CLUSTERED

    apply hysteresis

    select estimator according to state

    compute estimator point estimate

    compute upper residual bound

    apply state-dependent safety multiplier

    if adjusted upper residual bound
       <= α * estimated total:

        STOP

Return:
    stopping time
    selected estimator
    final observation state
    estimator transition history
```

# 29. The key result we want

The ideal result is NOT simply:

```text
AAARS has the lowest stopping time.
```

The key desired result is:

```text
AAARS maintains low false-certification
while avoiding unnecessary conservatism.
```

In particular, the expected behavior is:

### BoustroLanes

AAARS should recognize dispersed observations and behave close to:

```text
Chao1
```

without sacrificing safety.

### MineRichness

AAARS should recognize clustered observations and become more conservative:

```text
AAARS ≈ conservative estimator
```

thereby reducing the 26.7–60% false-certification problem.

The desired outcome is:

```text
AAARS
    ≈ Chao1 efficiency when safe
    ≈ conservative estimator when risky
```

This is the central hypothesis.

# 34. Main hypothesis

Formally state:

### H1

AAARS reduces false certification relative to fixed Chao1 stopping under locality-driven allocation.

### H2

AAARS achieves lower stopping cost than an always-conservative stopping rule while maintaining comparable safety.

### H3

AAARS adapts its estimator choice consistently with measurable observation-process characteristics.

### H4

Removing the allocation diagnostics reduces either safety or efficiency.

These hypotheses should drive the experiments.

```text

    << Chao1 under MineRichness

    << always-conservative estimator

AND

    remains high

    under safe/systematic allocation.
```

> **AAARS adapts the conservatism of richness-based stopping to the statistical risk induced by robot allocation, rather than committing to one estimator for all observation processes.**
